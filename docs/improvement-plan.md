# 📋 برنامهٔ پیشنهادی بهبود — مدیر و اعضا

> حاصل بازبینی کامل صفحات، APIها، کران‌ها و الگوهای رابط کاربری (۱۴۰۵/۰۶/۲۰).
> اولویت‌ها: 🔴 بیشترین ارزش برای کاربر نهایی · 🟡 متوسط · 🟢 کوچک/سریع

## 👤 برای اعضا (ساکنین/مالکان)

### ✅ ۱. داشبورد ساکن تقریباً خالی است — «کارت واحد من» (انجام شد)
الان ساکن در داشبورد فقط هدر + دو ویجت می‌بیند (آمار و ویجت‌های مالی فقط برای مدیر است).
**پیشنهاد:** کارت «واحد من» برای ساکن شامل:
- ماندهٔ حساب واحد (بدهکار/طلبکار) از `GET /buildings/{id}/unit-balances` (فیلتر واحدِ کاربر)
- جمع پرداخت‌نشده‌ها + دکمهٔ «پرداخت» به `costs.php`
- مشخصات: شماره واحد، طبقه/بلوک، پارکینگ/انباری، تعداد نفرات، شارژ دلخواه
- مهلت پرداخت بعدی (اگر هزینه دارای `due_date` فعال است)

### ✅ ۲. اعلان برای اطلاعیه‌ها وجود ندارد (انجام شد)
ثبت اطلاعیه هیچ اعلان درون‌اپ/پیامکی برای اعضا نمی‌سازد — مهم‌ترین کانال ارتباطی ساختمان عملاً ساکت است.
**پیشنهاد:** هنگام ایجاد اطلاعیه، اعلان برای همهٔ اعضای فعال ساختمان + (اختیاری) پیامک مثل کران بدهکاران.

### ✅ ۳. اعلان پاسخ/تغییر وضعیت تیکت (انجام شد)
`TicketService` هیچ اعلانی نمی‌سازد؛ ساکن نمی‌فهمد مدیر جواب داده یا وضعیت عوض شده (و برعکس).
**پیشنهاد:** اعلان به ایجادکننده هنگام پاسخ/تغییر وضعیت، و به مدیر هنگام ثبت تیکت جدید.

### ✅ ۴. اعلان شروع رأی‌گیری (انجام شد)
رأی‌گیری جدید بدون اعلان دیده نمی‌شود → مشارکت کم.

### ✅ ۵. تقویم: مهلت‌های پرداخت (انجام شد)
تقویم فقط جلسه‌ها و رزروها را نشان می‌دهد. اضافه‌شدن «مهلت پرداخت هزینه‌ها» (به‌ویژه برای واحد خود ساکن) ارزش بالایی دارد.

### ✅ ۶. پروفایل: خلاصهٔ نقش‌ها و واحدها (انجام شد)
در `profile.php` فهرست ساختمان‌ها با نقش و واحد مرتبط هر کاربر نمایش داده شود (لینک به داشبورد هر ساختمان).

## 🅜 برای مدیر

### 🔴 ۷. یادآور مهلت پرداخت (کران)
`scripts/reminders.php` فقط جلسه/رزرو را یادآوری می‌کند. مهم‌ترین ابزار مدیر: یادآور سررسید شارژ/هزینه به واحدهای پرداخت‌نکرده (اعلان + پیامک، مثل یادآور بدهکاران) — قابل تنظیم از پنل مدیر.

### 🔴 ۸. اعلان‌های مدیریتی گم‌شده
- ثبت هزینه/صدور هزینه برای اعضا → اعلان «هزینهٔ جدید صادر شد» (الان فقط برخی مسیرها اعلان دارند)
- تأیید/رد پرداخت → اعلان به پرداخت‌کننده (بررسی شود کدام مسیرها کم دارند)
- درخواست تعمیر جدید → اعلان به مدیر
- رزرو جدید مشاعات → اعلان به مدیر

### 🟡 ۹. جستجو + صفحه‌بندی در فهرست‌های باقی‌مانده
الان فقط `costs` · `members` · `audit_logs` دارند. فهرست‌های بلند بدون جستجو:
تیکت‌ها · واحدها · اطلاعیه‌ها · اسناد · رزروها · مهمان‌ها · تعمیرات · رأی‌گیری‌ها · جلسات
(زیرساخت آماده است — فقط اتصال `data-list-items` به هر صفحه)

### 🟡 ۱۰. خروجی اکسل/CSV برای فهرست‌های پرکاربرد
اعضا · پرداخت‌ها · تیکت‌ها (زیرساخت `reports_export` موجود است).

### 🟢 ۱۱. تصویر دلخواه برای ساختمان
الان فقط ۴ تصویر پیش‌فرض رادیویی. آپلود تصویر اختصاصی با همان زیرساخت `FileStorage` (مثل اسناد/فیش‌ها) + مهار دسترسی.

### 🟢 ۱۲. یادآوری تمدید/انقضای دعوت‌نامه‌ها
دعوت‌های ۷روزه بی‌خبر منقضی می‌شوند؛ اعلان به مدیر یک روز قبل از انقضا.

## 🎨 مشترک (هر دو نقش)

### 🟡 ۱۳. اسکلت بارگذاری (Skeleton) واقعاً استفاده شود
کلاس‌های اسکلت در `style.css` هست ولی **هیچ صفحه‌ای استفاده نمی‌کند**. افزودن به داشبورد، هزینه‌ها و تیکت‌ها (صفحه‌های سنگین با چند درخواست API) تجربه را حرفه‌ای می‌کند.

### 🟡 ۱۴. حالت شب: رنگ‌های ثابتِ روشن در چند صفحه
- چیپ‌های `bg-emerald-50 / bg-amber-50 / ...` (Tailwind روشن) در پروفایل ساختمان و هزینه‌ها در حالت شب همان روشن می‌مانند → نیاز به معادل تیره یا کلاس اختصاصی.
- هشدار آبیِ «شما با نقش … وارد شده‌اید» در داشبورد استایل اینلاین دارد → کلاس `app-alert-info` با نسخهٔ تیره.

### 🟢 ۱۵. بهبود کارایی داشبورد
داشبورد ~۱۰ درخواست API می‌زند (اعضا، واحدها، بلوک‌ها، طبقات، تیکت‌ها، مانده‌ها و…). یک اندپوینت تجمیعی `GET /buildings/{id}/dashboard` تعداد رفت‌وآمدها را کم و صفحه را سریع‌تر می‌کند (به‌ویژه روی هاست اشتراکی).

### 🟢 ۱۶. اعلان‌ها: «خواندن همه» + فیلتر
دکمهٔ یک‌کلیک برای خواندن‌کردن همهٔ اعلان‌ها + تفکیک مالی/عمومی.

### 🟢 ۱۷. پیام‌ها: نشان خوانده‌شدن
وضعیت «دیده شد» برای پیام‌های طرف مقابل.
