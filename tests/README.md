# تست‌ها و لاگ‌گیری

## اجرای تست‌ها

```bash
php tests/Integration/run.php              # همه سوئیت‌ها
php tests/Integration/run.php otp user     # فقط سوئیت‌های مشخص
```

در حال حاضر **۸۴۰ تست** در ۲۵ سوئیت اجرا می‌شود.
خروجی رنگی است و در پایان خلاصه‌ای از تست‌های موفق/ناموفق چاپ می‌شود.
کد خروجی در صورت شکست `1` است، پس در CI مستقیم قابل استفاده است.

### سوئیت‌ها

| سوئیت | موضوع |
|---|---|
| `logger` | لاگ‌گیر مرکزی: سطوح، پنهان‌سازی داده حساس، ثبت استثنا، `guard` |
| `handlers` | گیرنده‌های سراسری خطا و نوشتن روی فایل |
| `phone` | نرمال‌سازی و اعتبارسنجی شماره موبایل (ارقام فارسی/عربی، +98، 0098) |
| `jalali` | تقویم شمسی: تبدیل میلادی↔جلالی، طول ماه/کبیشه، قالب‌بندی، رفت‌وبرگشت ۱۰۰۰ روزه |
| `validator` | اعتبارسنج ساده فرم‌ها |
| `otp` | کد یک‌بارمصرف: انقضا، بازه ارسال مجدد، سقف تلاش، سقف ساعتی، هش‌شدن کد |
| `user` | جریان کامل ورود/ثبت‌نام با شماره: `phoneStatus` → OTP → نام → رمز |
| `charge` | سه حالت شارژ: ثابت، نفری، دلخواه + ثبت خودکار شارژ ماهانه |
| `costissue` | صدور هزینه برای مخاطبان انتخابی: اعتبارسنجی، سهم مساوی/متراژ، مستأجرین/ساکنین/واحدهای خاص، اعلان، بدون ردیف تکراری |
| `accounting` | حسابداری واحد: نشست پرداخت تأییدشده به حساب واحد، مانده بدهکار/طلبکار، جریمه تأخیر |
| `roles` | مدیر / مالک / مستأجر و تعیین ساکن‌بودن |
| `documents` | اسناد ساختمان: ثبت فقط مدیر، آپلود امن با نام تصادفی و .htaccess، نرمال‌سازی دسته‌ها، رویت اعضا/مدیر، تعویض فایل، حذف رکورد+فایل، ضد پیمایش مسیر |
| `votes` | رأی‌گیری و نظرات: ایجاد/بستن فقط مدیر، یک‌رأی بودن، رأی زودهنگام/پس از بستن ممنوع، درصد نتایج، مالکیت نظرات |
| `bulkusers` | ساخت گروهی کاربران: اتصال مالک/مستاجر به واحد، خطای ردیف‌ها، واحد پُر با/بدون جایگزینی، اتصال شمارهٔ موجود |
| `audit` | لاگ ممیزی: ثبت اقدام‌های مالی به‌ترتیب، متادیتای JSON، بدون شکستن عملیات اصلی |
| `security` | تنظیمات امن، محدودیت نرخ ورود، محافظت CSRF |
| `reports` | گزارش ماهانه (تفکیک ماه شمسی)، فهرست بدهکاران با آستانه، اجرای خشک/غیرفعال یادآوری پیامکی و کلید ضدتکرار |
| `messaging` | صندوق پیام خصوصی: ارسال/گفتگوها/نخوانده‌ها، خوانده‌شدن خودکار، دسترسی اعضا، محدودیت متن |
| `invitations` | دعوت‌نامه: صدور با توکن، اعتبارسنجی نام/شماره، لغو توسط مدیر و مسدودسازی غیرمدیر |
| `notifications` | اعلان‌ها: پخش سراسری اطلاعیه/رأی‌گیری، اعلان دوطرفهٔ تیکت/رزرو/تعمیرات و «خواندن همه» |
| `payment_reminders` | یادآور مهلت پرداخت: آستانهٔ روز، ضدتکرار، اعلان درون‌برنامه‌ای + پیامک (خشک/غیرفعال) |
| `dashboard` | اندپوینت تجمیعی داشبورد: همهٔ بخش‌ها در یک درخواست، دسترسی عضو/غیرعضو |
| `openapi` | اعتبار `docs/openapi.json` و همگام‌سازی دوطرفه با جدول روت‌ها + وجود دروازهٔ کیفیت (PHPStan) |
| `codebase` | بازرسی سلامت کل مخزن (الگوهای خطاخیز در همه فایل‌ها) |
| `e2e` | رندر همهٔ صفحات اپ با دادهٔ واقعی از مسیر کرنل (بدون خطای مهلک، فرم‌ها با CSRF) |

سوئیت `costissue` چرخهٔ تأیید/رد پرداخت و ماندهٔ بدهکار/طلبکار هر واحد را هم پوشش می‌دهد.

### زیرساخت

`tests/Integration/bootstrap.php` یک پایگاه‌داده **SQLite در حافظه** می‌سازد و آن را
از طریق Reflection داخل `App\Core\Database` تزریق می‌کند. به این ترتیب سرویس‌های
واقعی برنامه بدون هیچ تغییری و بدون نیاز به MySQL اجرا و تست می‌شوند.

توابع کمکی: `test_db()`، `test_db_reset()`، `make_user()`، `make_building()`،
`add_member()`، `make_unit()`.

## لاگ‌گیری

`App\Core\Logger` نقطه واحد گزارش مشکلات در کل برنامه است.

```php
use App\Core\Logger;

Logger::info('CostService', 'شارژ ماهانه ثبت شد', ['building_id' => 12]);
Logger::error('SmsService', 'ارسال پیامک ناموفق بود', ['to' => $phone], $e);
Logger::exception('AuthController', $e, ['phone' => $phone]);

// اجرای امن کار جانبی: در صورت خطا فقط لاگ می‌شود و برنامه ادامه می‌یابد
$result = Logger::guard('CostService', 'محاسبه شارژ', fn() => $svc->calc($id), fallback: []);
```

### سطوح

`debug` → `info` → `warning` → `error` → `critical`

### خروجی

خط‌های JSON در `storage/logs/app-YYYY-MM-DD.log`. هر رکورد شامل زمان، سطح،
کانال، پیام، زمینه (context) و اطلاعات درخواست (متد، مسیر، IP، شناسه کاربر) است.
اگر مسیر لاگ قابل نوشتن نباشد، به `error_log` پیش‌فرض PHP برمی‌گردد — لاگ‌گیری
هرگز باعث خطا در برنامه نمی‌شود.

### امنیت

کلیدهای حساس (`password`، `token`، `code`، `otp`، `secret` و مشابه) به‌صورت
بازگشتی با `[redacted]` جایگزین می‌شوند؛ حتی در آرایه‌های تودرتو.

### تنظیمات محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `APP_LOG_DIR` | `storage/logs` | مسیر پوشه لاگ |
| `APP_LOG_LEVEL` | `info` | حداقل سطح ثبت‌شده |
| `OTP_DEBUG` | — | با مقدار `1` کد یک‌بارمصرف در پاسخ API برگردانده می‌شود (فقط توسعه) |

### گیرنده‌های سراسری

`Logger::install()` در `includes/api_helper.php` (صفحات) و `public/index.php` (API)
صدا زده می‌شود و هشدارهای PHP، استثناهای مدیریت‌نشده و خطاهای مرگبار (fatal) را
ثبت می‌کند. خطاهای سرکوب‌شده با `@` عمداً نادیده گرفته می‌شوند.

## امنیت

### اسرار

هیچ رمز یا کلیدی در کد نیست. همه از متغیرهای محیطی خوانده می‌شوند:

```bash
cp .env.example .env
# سپس JWT_SECRET و DB_PASSWORD را پر کنید
openssl rand -base64 48   # برای ساخت JWT_SECRET
```

در محیط تولید (`APP_ENV=production`) نبودِ `JWT_SECRET` یا `DB_PASSWORD`
باعث خطای صریح می‌شود تا برنامه با تنظیمات ناامن بالا نیاید.
`APP_ENV` پیش‌فرض `production` است — یعنی فراموش‌کردنش خطرناک نیست.

### محافظت CSRF

هر درخواست POST باید توکن معتبر جلسه داشته باشد. اعتبارسنجی به‌صورت خودکار
در `includes/api_helper.php` انجام می‌شود و درخواست بدون توکن با کد ۴۱۹ رد می‌شود.

در فرم‌های جدید فقط کافی است این را اضافه کنید:

```php
<form method="POST">
    <?= csrf_field() ?>
    <input type="hidden" name="form_action" value="create">
    ...
</form>
```

### محدودیت نرخ ورود

`App\Services\RateLimiter` از حمله جست‌وجوی فراگیر روی رمز عبور جلوگیری می‌کند:
پنج تلاش ناموفق در پانزده دقیقه، سپس پاسخ ۴۲۹. ورود موفق سابقه را پاک می‌کند.
کلیدها (شماره + IP) به‌صورت SHA-256 ذخیره می‌شوند تا داده خام در جدول نماند.

## بررسی سلامت

پیش از هر استقرار:

```bash
php scripts/healthcheck.php          # بررسی کامل شامل پایگاه‌داده
php scripts/healthcheck.php --ci     # فقط بررسی‌های ایستا
```

نسخه PHP، افزونه‌ها، تنظیمات حیاتی، دسترسی نوشتن، وجود جدول‌ها و
اعمال‌شدن مایگریشن‌ها را بررسی می‌کند. کد خروجی در صورت مشکل بحرانی `1` است.

## مایگریشن‌ها

```bash
php scripts/migrator.php --status    # چه چیزی در انتظار است
php scripts/migrator.php             # اجرای مایگریشن‌های اعمال‌نشده
```

سابقه در جدول `migrations` نگه‌داری می‌شود، پس اجرای دوباره بی‌خطر است.

## یکپارچگی پیوسته

یک workflow آماده در `ci/github-actions.yml.example` هست که روی هر push و PR
بررسی نحوی، تست‌ها و بررسی آمادگی تولید را اجرا می‌کند.

برای فعال‌سازی، راهنمای `ci/README.md` را ببینید (به دلیل محدودیت دسترسی،
فایل workflow باید یک بار به‌صورت دستی در `.github/workflows/` کپی شود).

## نکته درباره tests/Unit

`tests/Unit/` (PHPUnit) برای سازگاری باقی مانده ولی محتوایش کاملاً در
سوئیت‌های `phone` و `validator` پوشش داده شده است. برای اجرا نیاز به
نصب کامل کامپوزر دارد؛ تست‌های یکپارچه هیچ وابستگی‌ای ندارند.
